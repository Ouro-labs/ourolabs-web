# ME

ME는 AI가 사용자의 경험과 일하는 맥락을 이해하도록 돕는다. 사용자를 고정된 유형으로 정의하는 검사가 아니다. 지금 업무에 도움이 될 정보를 충분히 탐색하되, 본인이 확인하고 수정할 수 있는 개인 컨텍스트를 남긴다. 사용자에게 긴 자기소개를 완성해 오라고 맡기지 말고 AI가 읽고 구조를 만들고 질문을 준비한다.

## 시작과 자료 요청

초회에는 먼저 다음처럼 자료를 요청한다. 이미 제공된 자료는 다시 요구하지 않는다.

> 이력서, LinkedIn 소개, 자기소개, 업무 메모 중 편하게 공유할 수 있는 자료가 있으면 한꺼번에 주세요. 없어도 괜찮습니다. 요즘 하는 일과 관심 있는 문제를 순서 없이 말씀해 주시면 시작할 수 있습니다. 비밀번호나 회사 기밀은 필요하지 않습니다.

자료 요청 단계에서 긴 설문을 붙이지 않는다. 사용자가 자료가 없다고 하거나 바로 이야기하면 업로드를 기다리지 말고 자유발화로 시작한다. 현재 어떤 업무에 이 맥락을 쓸지도 함께 파악한다. 목적이 아직 넓으면 ‘업무에 쓸 개인 맥락 정리’라는 잠정 범위에서 시작하고 좁혀 간다.

제공된 파일·본문·접근 가능한 대화를 실제로 읽는다. 링크는 읽을 수 있을 때만 확인하고, 접근이 안 되면 관련 부분의 복사나 자유 설명으로 대신한다. LinkedIn 로그인, 대화 추출 스크립트, 특정 보조도구, 외부 계정 연결을 요구하지 않는다. 보이지 않는 과거 대화를 기억한다고 하지 않는다.

## 구조 초안

자료가 있으면 먼저 읽고 구조 초안을 제시한 뒤 질문한다. 자료가 없으면 자유발화에서 드러난 범위로 잠정 구조를 만들고, 모르는 부분을 표시한 뒤 분야별 묶음으로 탐색한다. 짧은 발언으로 완성된 인물상을 만들지 않는다.

초안은 다음 분야를 검토하되, 지금 업무와 관련된 분야를 중심으로 구성한다. 초기에는 관련성을 너무 빨리 단정하지 말고 실제 경험을 넓게 탐색한다.

- 현재 역할과 책임, 전문 분야와 판단 기준.
- 주요 경험과 본인 기여, 반복 업무와 어려움.
- 관심과 지향, 현재의 변화와 제약.
- 소통·학습·작업 선호, AI와 협업할 때 본인이 유지할 역할.

각 진술을 아래 네 종류로 구분한다. 혼합된 진술은 나눈다.

| 종류 | 기록 기준 |
| --- | --- |
| 사실 | 자료 또는 본인 발언에 명시된 사건·역할·행동. 본인 진술과 독립 검증을 구별하고 출처를 적는다. |
| 본인선호 | 본인이 직접 밝힌 방식·좋고 싫음·우선순위. 적용 상황을 적고 모든 업무의 영구 규칙으로 확대하지 않는다. |
| 해석 | AI가 단서에서 추론한 의미. 단서와 추론 이유, 확인 상태를 적는다. 본인이 동의해도 객관적 사실로 바꾸지 않는다. |
| 미확인 | 자료가 없거나 충돌하거나 판단할 수 없는 내용. 필요한 확인과 업무에 미치는 영향을 적는다. |

근거에는 자료명·해당 부분 또는 본인 발언을 적고, **자료 작성일·내용이 적용되는 시점·본인 확인일**을 구별한다. 알 수 없는 날짜는 ‘날짜 미상’으로 둔다. 이력서의 예전 직함을 현재 역할로 복사하지 않는다. 목표를 성과로, 팀 성과를 개인 성과로, 사례 한 번을 성향으로 바꾸지 않는다.

## 분야별 탐색

처음 만난 사람에게는 처음 떠오른 몇 가지 질문만으로 탐색을 끝내지 않는다. [질문 은행](#질문-은행)의 10분야를 누락 점검에 활용하고, 역할·전문성·경험·판단·선호·제약을 두루 살펴 현재 업무에 필요한 맥락을 확보한다. 모든 분야의 답을 수집하는 것이 목적은 아니다.

질문은 **분야별 묶음**으로 제시한다. 한 묶음 3~5개는 읽기 쉬운 예시이며 총 질문 수의 제한이 아니다. 사용자의 답과 피로도에 따라 크기를 조정하고, 필요한 분야는 여러 묶음에 걸쳐 계속 탐색한다. 한 개씩 묻거나 200문항을 순서대로 설문하지 않는다. 이미 답이 드러난 질문은 다시 묻지 않는다. ‘자료에 있음 / 확인 필요 / 생략’으로 내부 점검해 중복을 막는다.

묶음 앞에 왜 이 분야를 묻는지 짧게 설명한다. 질문에는 가능한 예상 답과 근거를 붙여, 사용자가 맞는지 확인하거나 틀린 부분만 고칠 수 있게 한다. 경험이 전혀 드러나지 않은 부분은 ‘아직 모름·자유 설명’ 또는 ‘미정으로 두기’를 제시한다. 근거 없는 인물상을 예상 답으로 만들어 유도하지 않는다.

| 번호 | 확인할 내용 | 예상 답·현재 이해 | 근거와 필요한 보충 |
| --- | --- | --- | --- |
| 1 | 현재 역할과 예전 경력 중 이번 업무에 중요한 것은 무엇인가요? | 현재 역할 중심, 예전 경력은 관련 경험만 / 단서가 없으면 자유 설명 | 자료의 역할과 날짜를 구분해 표시 |

“맞는 내용은 그대로, 틀린 번호는 수정할 부분만 알려 주세요. 경험을 덧붙이거나 미정·생략으로 남겨도 됩니다”라고 안내한다. 답을 반영한 뒤 새로 생긴 빈칸과 아직 필요한 분야만 다음 묶음에 올린다. 답을 기다리는 동안 예상 답을 확정 프로필로 사용하지 않는다.

현재 업무에 필요한 맥락이 충분하고 중대한 오해가 없으면 문서 확인으로 넘어간다. 사용자가 멈추길 원하거나 일부를 생략하면 미확인·생략을 남기고 종료할 수 있다. 모든 사람에게 동일한 질문 수를 강제하지 않는다.

## 충돌과 변화

기존 프로필과 새 자료가 다르면 먼저 같은 시점·같은 상황에 대한 진술인지 확인한다. 예전에는 혼자 작성했고 지금은 팀 검토를 선호한다면 시점 변화일 수 있다. 현재 업무와 다른 업무의 선호 차이라면 상황별 차이로 남긴다. 같은 시점의 역할이 서로 다르면 해결되지 않은 자료 충돌이다.

충돌한 출처·적용 시점과 가능한 해석을 묶어 제시하고, 현재 어느 설명을 사용할지 본인에게 확인한다. 단순히 최신 파일이라는 이유로 채택하거나 평균내지 않는다. 확인 전에는 기존의 확인된 내용을 조용히 덮어쓰지 않고 새 정보를 미확인 변경안으로 둔다. 사용자가 현재 상태와 변화 시점을 명확히 확인하면 현재 내용을 갱신하고, 필요한 이전 맥락과 변경 이유를 짧게 남긴다.

## 정보 범위

현재 업무 목적에 필요한 개인정보만 수집·저장한다. 연락처·주소·고객 실명·인증정보 등 불필요한 세부정보가 자료에 있어도 초안이나 질문에서 재노출하지 않는다. 회사 기밀을 요구하지 않고, 공개 자료·익명화한 사례·추상화한 업무 설명으로 이어 간다. 자료 공유를 거절해도 실습을 중단하지 않는다.

민감한 내용은 장문의 원문 대신 업무상 필요한 제약만 남긴다. 저장에서 빼 달라는 항목은 문서에서 제외하고, 제외 기록에도 원문을 반복하지 않는다. 다른 대화나 원본 파일까지 삭제했다거나 서비스의 보관 방식이 바뀌었다고 주장하지 않는다.

MBTI·사주는 사용자가 원해서 제공할 때만 선택 참고로 둔다. 생년월일·출생시각이나 검사를 요구하지 않는다. 직업 적합성·능력·성향을 단정하는 근거로 쓰지 않으며, 실제 행동과 본인이 설명한 선호를 우선한다.

## 본인 확인

질문 답을 반영한 전체 초안을 보여준다. 해석과 미확인 사항, 제외할 정보가 눈에 보이게 하고 다음처럼 확인한다.

> 지금 업무에 사용할 개인 컨텍스트 초안입니다. 실제와 다른 점, 상황에 따라 달라지는 점, 저장에서 뺄 내용을 알려 주세요. 이 범위로 확인해도 될까요?

질문 묶음 확인과 전체 문서 확인을 구별한다. 명시적인 확인 전에는 초안이며, 미응답은 동의가 아니다. 일부만 확인하면 진술별 상태를 보존한다. 본인 확인은 해당 날짜·상황에서의 확인이며 영구적인 정체성 확정이 아니다. 사용자가 동의한 해석은 ‘해석·본인 동의’로 남기고 성향을 사실로 승격하지 않는다.

## 저장과 갱신

파일을 쓸 수 있으면 사용자가 지정한 작업 폴더에 `ME.md`로 저장한다. 위치가 없으면 현재 작업 폴더의 사용 가능한 위치를 확인하고 저장 위치를 알린다. 같은 사용자의 기존 개인 컨텍스트가 제공되면 이름을 강제로 바꾸지 않고 그 문서를 읽어 갱신한다. 다른 사람이나 관계없는 파일을 덮어쓰지 않는다. 초안 저장은 가능하되 확인 완료로 표시하지 않는다.

파일 쓰기가 불가능하면 복사해 저장할 Markdown 전문을 제공한다. 특정 앱·글로벌 경로·자동 기억 기능에 의존하지 않는다. 실제 파일을 쓰지 않았다면 ‘저장 완료’라고 하지 않는다.

```markdown
# 개인 컨텍스트

상태: 초안 / 일부 확인 / 본인 확인 완료
활용 범위: 현재 업무와 사용 목적
작성·갱신일: 실제 날짜

## 현재 맥락
역할·전문성·관련 경험

## 판단과 협업
판단 기준·본인선호·AI와 본인의 역할

## 정보 기록
| 내용 | 종류 | 근거 | 자료 작성일 | 적용 시점·상황 | 본인 확인일·상태 |
| --- | --- | --- | --- | --- | --- |

## 미확인 사항
자료 충돌·남은 질문·생략한 분야의 영향

## 변경 기록
바뀐 내용과 이유·적용 시점·확인 상태
```

근거 없는 빈칸은 채우지 않는다. 기존 문서 갱신 시 관련 변경만 반영하고, 시점 변화와 단순 정정을 구별한다. 질문 답 때문에 해석이 바뀌면 그 해석에 의존한 문장도 함께 재점검한다.

## 재사용과 연결

새 업무에서는 전체 프로필을 무조건 붙이지 않는다. 사용자가 제공한 `ME.md`와 현재 요청을 읽고, 관련 역할·경험·선호·제약만 선별한다. 오래되었거나 상황이 맞지 않는 내용은 재확인하고, 이번 업무 한 번의 선택을 개인의 영구 선호로 자동 저장하지 않는다. 지속적인 선호 변경은 적용 범위를 확인한 뒤 갱신한다.

ME는 ‘이 사람의 어떤 맥락을 고려할 것인가’를 맡는다. WIW는 ‘이번 작업으로 무엇을 이루려는가’를, II는 ‘작업을 위해 무엇을 결정해야 하는가’를 맡는다. 제공된 의도 문장과 결정 사항은 참조하되 ME에서 다시 인터뷰하거나 별도 결정을 만들지 않는다. 작업 의도가 불분명하면 WIW 방식의 의도 확인으로, 구현 범위·기한·승인 같은 미정 선택은 II 방식의 예상 답 묶음으로 연결한다. 두 스킬이 설치되지 않아도 이 구분을 대화에서 적용할 수 있다.

마지막에는 저장 경로 또는 복사할 본문, 본인 확인 범위, 남은 미확인 사항, 다음 업무에서 가져갈 핵심 맥락을 짧게 알린다. 다음 대화에 문서를 다시 제공하거나 읽게 해야 하며, 저장만으로 모든 대화의 기억이나 전역 설정이 바뀐다고 설명하지 않는다.


## 질문 은행

# 개인 컨텍스트 질문 은행

이 문서는 AI가 자료에서 빠진 맥락을 찾기 위한 참고자료다. **참가자에게 200문항을 순서대로 묻거나 전부 답하도록 요구하지 않는다.** 먼저 자료와 자유발화로 초안을 만들고, 현재 업무에 필요한 맥락을 분야별 질문 묶음으로 충분히 탐색한다. 한 묶음 3~5개는 예시이며 총 질문 수 제한이 아니다. 필요한 분야는 추가 묶음으로 계속 확인한다. 이미 답이 드러난 질문은 제외하고, 관계없는 분야와 말하고 싶지 않은 항목은 생략한다. 이력서가 없어도 사용할 수 있다.

10분야에 각각 20개, 총 200개 질문이 있다. 분야 번호는 질문 순서가 아니다. 원자료에 없는 답은 추측해 사실로 채우지 않는다. 비밀번호·인증정보·회사 기밀·식별 가능한 고객 정보는 요구하지 않는다.
