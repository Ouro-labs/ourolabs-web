# WIW

WIW는 What I Want다. 사용자가 무엇을 얻고 싶은지 먼저 밝히고, 긴 작업에서도 그 의도를 유지한다.

## 의도 파악

현재 접근 가능한 대화의 사용자 발언을 처음부터 읽고, 사용자가 제공한 자료를 함께 본다. 이유, 원하는 변화, 지켜야 할 조건을 직접 설명한 말을 우선한다. “다시”, “이 도구로” 같은 작업 지시만으로 목적을 정하지 않는다. 요약이나 이전 의도 문장만 보고 원래 발언을 읽었다고 하지 않는다.

과거 대화가 보이지 않으면 그 한계를 밝히고 현재 보이는 말로 잠정 정리한다. 대화 기록 추출 스크립트, 개인 경로, 특정 도구 설치를 요구하지 않는다. 꼭 필요한 경우에만 관련 발언을 붙여 달라고 요청한다.

사용자에게 어떤 상태가 이루어져야 하는지를 먼저 쓰고, 그 상태를 위해 만들거나 할 일을 이어 한 문장으로 정리한다. 제품·문서·스킬은 대개 수단이다. 사용자의 구체적인 핵심어와 방식·조건을 보존하며, 은유만 평이하게 푼다. 다른 프로젝트에도 그대로 적용될 만큼 넓은 문장은 피한다. 일회성 이름·날짜·버그는 제외하되 사용자가 중요하게 정한 조건은 남긴다. 한 문장에 담기 어려울 때만 두 문장을 쓴다.

## 확인

답변 첫 줄에 의도 문장을 쓴다. 아래에는 근거가 된 사용자 발언 2~5개를 짧고 정확하게 인용한다. 발언이 적으면 있는 만큼만 쓰고 자료에서 얻은 단서는 출처를 구별한다. 인용을 만들어 개수를 맞추지 않는다. 사용자가 문장을 확인할 수 있는 정보만 덧붙인다.

사용자가 틀렸다고 하면 마지막 수정 요청을 기존 문장에 끼워 넣지 말고, 접근 가능한 사용자 발언 전체를 다시 읽어 의도를 재구성한다. 반려된 의도를 대체하는 초안에 의존한 작업은 새 확인을 기다린다.

## 기록과 재개

파일 쓰기가 가능하면 작업 폴더의 `intent.md`를 먼저 읽고 초안을 기록한다. 기존 내용 중 관계없는 부분은 보존한다. 파일 쓰기가 불가능하면 아래 형식의 복사 가능한 본문을 제공한다.

```markdown
# 의도

상태: 초안
갱신일: 실제 날짜

## 의도 문장
사용자가 원하는 결과와 그 수단

## 근거
사용자 발언의 짧은 인용과 대화 위치·자료명

## 결정 사항
사용자가 확인한 내용

## 미결 사항
아직 확인하지 못한 내용
```

명시적으로 확인받은 뒤에만 상태를 “본인 확인 완료”로 바꾼다. 미응답을 동의로 보지 않는다. 저장 위치와 상태를 알린다. 재개할 때는 이 문서와 그 뒤의 사용자 발언을 함께 읽는다. 새 대화에서 문서가 보이지 않으면 사용자에게 다시 제공받는다.

## II 연계

II도 요청되면 의도 문장을 예상 답의 기준으로 쓴다. II에서 확인한 답은 같은 의도 문서의 결정 사항에 기록한다. 확인된 답이 목적 자체를 바꾸면 의도 문장도 수정하고 확인받는다. II가 설치되어 있어야만 WIW를 사용할 수 있는 것은 아니다.
